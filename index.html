Section 05 — Critical Gaps
Where the product breaks down

Five gaps identified through PM analysis. The pipeline steps are verified; the gaps are analytical judgements about what the described system is missing.

INFERRED — gaps are based on what Troopod's own descriptions don't cover, not confirmed production bugs.

G1
No Verifier Agent — outputs go directly from generation to production
The published pipeline is: AI Prediction → Content Assembly → Delivery. No quality gate is described between assembly and delivery. A hallucinated headline, off-brand CTA, or recommendation for an out-of-stock product can be injected into a live storefront. At 52,000 visitors/month, even a 2% bad-output rate = 1,040 degraded brand experiences per day.
Critical
G2
Learning loop feedback depth is unclear — what signal closes the loop?
The blog confirms accuracy improves from 62% → 87% over 12 months but doesn't describe the attribution signal. If the feedback is coarse (session converted / didn't convert), the system can't distinguish a bad recommendation that got lucky from a good one that didn't. Without granular attribution, iteration is partly blind.
High Impact
G3
Ad-to-page matching is reactive — fires after an ad is already live
Dynamic landing pages are generated after a campaign launches. A predictive system would flag message-match problems at ad creation time — "your ad promises '14-day results' but your page has no proof of that claim" — before the brand spends ₹1. This shift would move Troopod upstream from reactive CRO tool to proactive campaign partner.
High Impact
G4
Checkout abandonment agent missing real-time event triggers
Checkout is the highest-intent moment in the funnel — the visitor has already chosen a product. The current system addresses post-session abandonment (retargeting, email). A real-time checkout agent that detects hesitation signals (cursor leaving window, long pause on payment field, scroll back to product) and injects trust nudges in the moment would directly cut the 73% checkout abandonment rate cited in their own case studies.
High Impact
G5
Agent output quality and conversion quality appear conflated in metrics
CVR is tracked as the primary success metric for the AI agent. But an agent can produce technically correct copy that doesn't convert (bad offer, wrong timing) and poor copy that does (right product, right moment). Without separating agent quality metrics (relevance score, hallucination rate, brand alignment) from business metrics (CVR, AOV), debugging is impossible. This is structurally the same flaw my IEEE paper documented in NLP model evaluation.

Section 06 — Agent Redesign Proposal
The pipeline I'd build to fix Gap 1

Insert a Verifier Agent between content assembly and Shopify delivery. Here's the exact architecture — using Troopod's JD language: planner → executor → verifier → memory.

ORIGINAL PROPOSAL — my design recommendation, not a Troopod feature.

troopod · agent-pipeline · v2 (proposed by Rahul Yadav · April 2026)
Planner

Intent Scorer

Scores visitor 0–100. Selects strategy: urgency / social proof / value. Outputs structured JSON with guardrails.

Executor

Content Generator

Generates personalised content as structured JSON: headline, CTA, product recs, trust signals, layout hints.

✦ NEW · Verifier

Quality Gate

Checks brand alignment, inventory sync, claim accuracy, relevance threshold. Routes: pass → deploy / fail → fallback / flag → human review.

Injector

Shopify Delivery

Only deploys verified content. Serves brand default for rejected outputs. Logs both pass and fail for attribution.

Memory

Attributed Feedback

Logs: which decision, which verifier score, which business outcome. Closes learning loop with granular attribution per cohort.

What the Verifier checks:

1. Brand alignment score — does copy match brand tone and product positioning?
2. Inventory sync — are recommended products in stock right now?
3. Claim accuracy — does "14-day results" appear in copy AND on the page?
4. Relevance threshold — is the intent signal strong enough to deviate from brand default?
Fallback routing (critical for production):

Relevance score < 0.6 → serve brand default
Inventory mismatch → swap to next-best in-stock product
Brand alignment < 0.7 → revert headline, keep layout personalisation

Key insight: A personalisation that feels "off" to a visitor is worse than no personalisation. The Verifier protects brand trust, not just CVR.

The defensible moat is the India-specific data flywheel: every brand onboarded teaches the model COD patterns, festival behaviour, and UPI conversion signals no US-built product can buy. Why I want to build this

My IEEE paper spent 15 months documenting exactly the structural problem in Gap 5 — evaluation metrics that make AI systems appear better than they are. The flaw I proved in NLP: apparent performance gains driven by measurement artefacts, not real improvement. Troopod's conflation of agent quality with business quality is the same issue.

My RAG project gave me the full pipeline: ingestion → chunking → embedding → retrieval → LLM output → evaluation. That's 80% of what a Troopod personalisation agent does. The missing 20% — CRO domain, Shopify execution — is what I'd be here to learn, fast.
